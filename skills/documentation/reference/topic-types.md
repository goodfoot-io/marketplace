# Reference: topic-type structures

Scope: the required structure of each topic type — a declarative checklist of what each must contain. Reference mode — look up while authoring. The authoring process is `../how-to/type-a-topic.md`.

## Concept / explanation

Title naming the concept · why it exists (problem it solves) before implementation · the learning outcome · scope (systems/versions/audiences) · examples from real use · links to prerequisite concepts, dependent tasks, and the formal reference. No embedded procedures.

## Task / how-to

The action as title and goal · the success/end-state, stated first · role and permission · prerequisites and required inputs before the steps · ordered, testable steps · verification (commands, checks, expected output) · failure routing and rollback (or an explicit "no rollback") · applicability branches only where behavior differs.

## Reference

Precise, structured scope · structured data (schemas, fields, states, commands, endpoints, limits, error codes) · a completeness marker within scope · source-of-truth and owner labels · examples marked normative or illustrative · version and per-value status (current/deprecated/experimental) · out-of-scope statement and adjacent links · generated from code with provenance where possible.

## Troubleshooting / runbook

Title from the user-visible symptom · diagnostics before fixes · causes ranked by probability/severity/cost · safe-vs-risky action markers · escalation thresholds and contacts · evidence to collect (logs, metrics, IDs, traces) · rollback/recovery path and post-fix verification · false-positive and lookalike notes · a runbook adds time-pressure, safety, and handoff structure.

## Glossary entry

Preferred term · definition · synonyms · scope · disambiguation ("not the same as") · related terms.
