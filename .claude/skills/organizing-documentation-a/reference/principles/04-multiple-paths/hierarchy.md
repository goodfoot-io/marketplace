# Hierarchy

Scope: choose one default navigation backbone and demote the rest to projections. Owns the primary-hierarchy decision for Principle 4.

## Diagnostics → actions

- **Choose the primary hierarchy** — usually the directory tree — as the default backbone.
- **More than one hierarchy is legitimate**: keep one as the backbone and express the others as facets, hubs, filters, and cross-links — `facets.md`.
- **Match each hierarchy to its view**: architecture/component, user workflow, operational ownership, learning order, troubleshooting paths each suit a different navigation need.
- **Decide what goes in main navigation**: promote the hierarchy that best balances common intent, business value, risk, onboarding needs, and operational urgency — `reference/principles/01-organize-around-user-intent/prioritization.md`.
- **A hierarchy is meaningful only to maintainers**: keep it backstage unless readers use it to find information — `reference/principles/05-controlled-vocabulary-and-metadata/retrieval.md`.
