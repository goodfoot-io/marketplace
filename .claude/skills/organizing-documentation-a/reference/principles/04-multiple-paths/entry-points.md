# Entry points

Scope: add the entry points matching how each reader tries to find a page. Owns the arrival-path model for Principle 4.

## Diagnostics → actions

- **A novice looks for it**: add beginner labels and onboarding links — `reference/principles/07-nonlinear-information-seeking/journeys.md`.
- **An expert looks for it**: add direct technical names and reference paths.
- **An operator looks for it during an incident**: add symptom, alert, and runbook links — `reference/principles/02-typed-source-of-truth-topics/troubleshooting-and-runbooks.md`.
- **A developer looks from code**: add API, module, class, function, repository, schema, and config aliases — `reference/principles/05-controlled-vocabulary-and-metadata/vocabulary.md`.
- **Support looks from a customer issue, or product from a feature name**: add customer-facing terms and product/feature synonyms — `reference/principles/05-controlled-vocabulary-and-metadata/vocabulary.md`.
- **A security or compliance reviewer looks for it**: add control, policy, risk, evidence, and audit metadata — `reference/principles/05-controlled-vocabulary-and-metadata/metadata-fields.md`.
- **Someone searches with the wrong term**: add aliases, redirects via links, and glossary entries — `reference/principles/06-information-scent/disambiguation.md`.
- **A reader arrives from a ticket, alert, dashboard, or error message**: link those artifacts back to the source-of-truth doc.
- **An agent retrieves the page with no navigation context**: give it clear headings, scoped aliases, an explicit scope line, source-of-truth links, and enough local context per chunk — `reference/principles/07-nonlinear-information-seeking/cross-reference.md`.
