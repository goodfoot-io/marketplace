# Hub scope

Scope: state each hub's scope, audience, organizing frame, and exclusions. Owns hub scoping for Principle 3.

## Diagnostics → actions

- **State the hub's scope in the opening line** — `reference/principles/06-information-scent/summaries-and-previews.md`.
- **State what is explicitly out of scope** and link adjacent hubs — `reference/principles/04-multiple-paths/cross-linking.md`.
- **Label the audience and expected prior knowledge** — `reference/principles/01-organize-around-user-intent/readers-and-roles.md`.
- **Declare the organizing frame** — domain, workflow, role, lifecycle stage, or problem class — and make it visible in the headings.
- **The hub has no single organizing principle**: reorganize it around one dominant frame.
- **The hub contains facts that belong in owned pages**: replace the detail with short summaries and links — `anti-duplication.md`.
- **A hub's routing quality is a concern distinct from the facts it links**: keep it accurate by routing to source-of-truth pages and the owning code areas — a hub gets no doc owner of its own — `reference/foundations.md`.
