# Hub content

Scope: decide what a hub holds beyond links — overview, map, status, onboarding and incident guidance. Owns hub composition for Principle 3.

## Diagnostics → actions

- **Add a short overview** — only enough to orient decisions, never a full explanation — `anti-duplication.md`.
- **Relationships matter**: add a domain map or diagram (an architecture-overview genre) — `reference/principles/02-typed-source-of-truth-topics/concept-pages.md`.
- **Add common tasks grouped by intent, common failure modes as troubleshooting entry points, key concepts, and key reference pages** — `reference/principles/01-organize-around-user-intent/intents.md`.
- **Rationale affects use**: link the decision records — `reference/foundations.md` decision-history layer.
- **Ownership or escalation is useful here**: add owner and escalation metadata — `reference/principles/08-validate-and-iterate/governance.md`.
- **Areas differ in maturity**: label beta, deprecated, legacy, experimental, or stable — `reference/principles/05-controlled-vocabulary-and-metadata/metadata-fields.md`.
- **Add a "new here?" onboarding path and an "under incident pressure?" emergency path** — `reference/principles/07-nonlinear-information-seeking/journeys.md`.
- **The hub is tempted to hold the facts**: instead point to the pages that own them — `anti-duplication.md`.
