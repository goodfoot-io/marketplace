# Concept and explanation pages

Scope: author concept/explanation pages — the why and the mental model. Owns concept-page structure for Principle 2.

## In the repo

An explanation belongs in a source-anchored wiki page when it synthesizes across files and answers "why" or "how it connects"; link the code as the owner of "what" (`reference/tools/wiki.md` inclusion test, `reference/foundations.md`).

## Diagnostics → actions

- **Set the title to the concept** as its opening promise — `reference/principles/06-information-scent/titles.md`.
- **Explain the problem it solves before implementation detail**; state the learning outcome near the top.
- **The page tempts a full procedure**: link a task page instead of embedding it — `task-pages.md`.
- **Add examples that match real use cases.**
- **There are prerequisite concepts**: link them before the explanation and include enough context for direct arrivals — `reference/principles/07-nonlinear-information-seeking/index.md`.
- **The concept is easily confused with another**: add comparison notes and disambiguating links — `reference/principles/06-information-scent/disambiguation.md`.
- **Tasks depend on this concept**: link forward to them — `reference/principles/04-multiple-paths/cross-linking.md`.
- **Formal details exist**: link the reference page, schema, or policy — `reference-pages.md`.
- **State the scope**: which systems, versions, environments, or audiences the explanation covers — `reference/principles/05-controlled-vocabulary-and-metadata/metadata-fields.md`.
