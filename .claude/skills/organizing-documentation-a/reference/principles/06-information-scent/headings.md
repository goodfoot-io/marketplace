# Headings

Scope: make headings informative signposts that reveal page logic and survive extraction. Owns heading design for Principle 6.

## In the repo

When an agent retrieves a chunk, the heading path is the context it gets. Keep headings specific so the path carries scope into a retrieval result (`reference/principles/07-nonlinear-information-seeking/cross-reference.md`).

## Diagnostics → actions

- **Headings do not support scanning**: rewrite them as informative signposts; shape them as the user's questions or tasks where useful.
- **A procedural section has a noun heading**: use a verb so the action is obvious.
- **Headings are inconsistent across topic types or genres**: standardize templates by mode and genre — `reference/principles/02-typed-source-of-truth-topics/modes-and-genres.md`.
- **The outline does not expose the answer's structure**: make headings reveal the page logic; promote answers buried under vague headings.
- **A section is too long to scan**: split it into subsections with their own signposts.
- **A skimmer cannot navigate**: add headings, callouts, summaries, and examples.
- **The table of contents does not carry meaning**: rewrite headings until a reader could judge relevance from the ToC alone.
