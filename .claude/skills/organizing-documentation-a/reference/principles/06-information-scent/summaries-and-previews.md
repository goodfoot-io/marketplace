# Summaries and previews

Scope: open every page and hub with a one-line scope/value statement that survives as a preview. Owns page openings for Principle 6.

## In the repo

The first line of a README or page is its summary; the wiki `summary` frontmatter is the preview source, and `wiki check` confirms title and summary resolve (`reference/tools/wiki.md`).

## Diagnostics → actions

- **A page has no opening summary**: add a one-sentence statement of scope and value.
- **A hub's scope is not immediate**: put it in the first paragraph — `reference/principles/03-hubs-orientation-and-routing/hub-scope.md`.
- **A search or retrieval preview lacks context**: improve the summary and the metadata used in previews — `reference/principles/05-controlled-vocabulary-and-metadata/retrieval.md`.
- **A matrix cell or link group is unclear before the click**: add a concise label or description — `reference/principles/04-multiple-paths/matrix-views.md`.
- **A page does not say who it is for, when to use it, or what it does not cover**: add audience, "use this when", and exclusion cues — `reference/principles/01-organize-around-user-intent/readers-and-roles.md`, `reference/principles/02-typed-source-of-truth-topics/modes-and-genres.md`.
- **A page mixes current and legacy, or normal and exceptional**: label the distinction — `reference/principles/05-controlled-vocabulary-and-metadata/metadata-fields.md`.
- **A page may be reached directly**: include enough context for readers who bypassed the hierarchy — `reference/principles/07-nonlinear-information-seeking/index.md`.
