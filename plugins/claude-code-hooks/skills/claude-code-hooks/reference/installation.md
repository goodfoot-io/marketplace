## 1. Prerequisites

- Node.js v20+
- Package manager: npm, yarn, pnpm, or bun
- TypeScript project (recommended)

## 2. Install Dependencies

```bash
# Using yarn (recommended)
yarn add @goodfoot/claude-code-hooks
yarn add -D tsx typescript

# Using npm
npm install @goodfoot/claude-code-hooks
npm install -D tsx typescript

# Using pnpm
pnpm add @goodfoot/claude-code-hooks
pnpm add -D tsx typescript
```

## 3. Create Hooks Directory

```bash
mkdir -p hooks
```

Recommended structure:

```
your-project/
├── hooks/
│   ├── pre-tool-use.ts      # PreToolUse hook
│   ├── session-start.ts     # SessionStart hook
│   └── stop.ts              # Stop hook
├── .claude/
│   └── hooks.json           # Generated by CLI
├── package.json
└── tsconfig.json
```

## 4. Create Your First Hook

Create `hooks/pre-tool-use.ts`:

```typescript
import { preToolUseHook, preToolUseOutput } from '@goodfoot/claude-code-hooks';

export default preToolUseHook({ matcher: 'Bash|Write|Edit' }, (input, { logger }) => {
  logger.info('Processing tool', { toolName: input.toolName });

  // Allow all tools by default
  return preToolUseOutput({
    hookSpecificOutput: { permissionDecision: 'allow' }
  });
});
```

## 5. Compile Hooks with CLI

Use the CLI to compile hooks and generate `hooks.json`:

```bash
npx claude-code-hooks -i "hooks/*.ts" -o ".claude/hooks.json"
```

This:
- Bundles each hook into a standalone `.mjs` file
- Extracts matchers from hook factory calls
- Generates `hooks.json` with correct paths and configuration
- Handles stdin/stdout and case transformation automatically

## 6. Test Your Compiled Hook

After compiling, test the generated hook:

```bash
echo '{"hook_event_name":"PreToolUse","tool_name":"Bash","tool_input":{"command":"ls -la"}}' | node .claude/pre-tool-use.*.mjs
```

Expected output:
```json
{"hook_specific_output":{"hook_event_name":"PreToolUse","permission_decision":"allow"}}
```

Note: The wire format uses snake_case. The hook factory pattern handles this transformation automatically.

## 7. TypeScript Configuration

For optimal type checking, add to your `tsconfig.json`:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true
  }
}
```

## 8. Hook File Template

Use this template for any hook type:

```typescript
// hooks/my-hook.ts
import {
  preToolUseHook,  // Replace with appropriate hook factory
  preToolUseOutput // Replace with appropriate output builder
} from '@goodfoot/claude-code-hooks';

export default preToolUseHook(
  { matcher: 'Bash' }, // Optional matcher config
  (input, { logger }) => {
    // Your hook logic here
    // Access input fields in camelCase: input.toolName, input.toolInput, etc.
    // Use logger for file-based logging

    // Return appropriate output
    return preToolUseOutput({
      hookSpecificOutput: { permissionDecision: 'allow' }
    });
  }
);
```

**All hook factories follow this pattern:**

| Hook Type | Factory | Config Options |
|-----------|---------|----------------|
| PreToolUse | `preToolUseHook()` | `matcher`, `timeout` |
| PostToolUse | `postToolUseHook()` | `matcher`, `timeout` |
| SessionStart | `sessionStartHook()` | `matcher` (startup\|resume\|clear\|compact) |
| Stop | `stopHook()` | `timeout` (no matcher) |
| PermissionRequest | `permissionRequestHook()` | `matcher`, `timeout` |
| *All others* | `{hookType}Hook()` | `matcher`, `timeout` |

## 9. Matcher Patterns

Matchers use regex to filter when hooks fire:

| Pattern | Matches |
|---------|---------|
| `Bash` | Only Bash tool |
| `Bash\|Write` | Bash OR Write tool |
| `Bash\|Write\|Edit` | Bash OR Write OR Edit |
| `.*` | All tools |
| `startup` | SessionStart on startup only |
| `startup\|resume` | SessionStart on startup or resume |

**Important**: Use escaped pipes (`\|`) in JSON for OR patterns.

## 10. Project-Level vs User-Level Hooks

Based on scope needed:
- **Project-specific rules**: Use `.claude/hooks.json`
- **Global personal hooks**: Use `~/.claude/hooks.json`
- **Global on XDG systems**: Use `~/.config/claude/hooks.json`

Project-level hooks take precedence when both exist.

## 11. Validation Checklist

After setup, verify:

- [ ] `@goodfoot/claude-code-hooks` is installed
- [ ] Hook files use hook factory pattern with `export default`
- [ ] CLI compilation succeeds: `npx claude-code-hooks -i "hooks/*.ts" -o ".claude/hooks.json"`
- [ ] `hooks.json` is generated with correct paths
- [ ] Compiled `.mjs` files are created in `.claude/`
- [ ] Test piping JSON to compiled hook produces valid output

## 12. Common Installation Issues

### 12.1 CLI Not Found

```bash
# Run via npx
npx claude-code-hooks -i "hooks/*.ts" -o ".claude/hooks.json"

# Or install globally
npm install -g @goodfoot/claude-code-hooks
```

### 12.2 Compilation Fails

Check hook file structure:
- Must use hook factory (e.g., `preToolUseHook()`)
- Must export default
- Must return output builder result

```typescript
// ✓ Correct
export default preToolUseHook({}, (input) => preToolUseOutput({}));

// ✗ Wrong - missing export default
preToolUseHook({}, (input) => preToolUseOutput({}));

// ✗ Wrong - using direct output builder without factory
const output = preToolUseOutput({});
process.exit(output.exitCode);
```

### 12.3 Module Not Found

Ensure `@goodfoot/claude-code-hooks` is installed:

```bash
# Check if installed
ls node_modules/@goodfoot/claude-code-hooks

# Reinstall if needed
yarn add @goodfoot/claude-code-hooks
```

### 12.4 Permission Denied on Compiled Hook

```bash
# Make compiled hooks executable
chmod +x .claude/*.mjs
```

### 12.5 Hook Not Triggering

Verify `hooks.json` was generated correctly and contains absolute paths:

```bash
cat .claude/hooks.json
```

Paths should be absolute like `/path/to/project/.claude/pre-tool-use.abc123.mjs`
